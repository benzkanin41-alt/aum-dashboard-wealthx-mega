# One-time target-date AUM cloud monitor

The new GitHub-hosted Linux workflow checks at minute 17 of each hour (all days).
This is a temporary target-date monitor, not a replacement for the existing
09:00 Bangkok daily updater. GitHub schedules may be delayed. No paid API,
local file, user PAT, database credential or running Windows computer is needed
by scheduled runs. The workflow uses its repository-scoped GITHUB_TOKEN only
for public issue notifications; it has contents:read and issues:write, no Pages,
deployment, secret, contents-write or action-management permissions.

Completeness means actual AUM dated exactly 2026-11-02 for all 72 frozen active
classes: 30 SeriesX, 33 MEGA30/TLUSHD and 9 other. Pending TLALLWEALTH-X is not
counted. Carried NAV, absent values and subsequent dates do not count as that
day. A changed eligible fund universe needs manual review, never silent removal.

Only scripts/run-sites-refresh.js may update canonical Sites data, using the
existing shared job, five-minute guard and checkpoint/resume semantics. A run
advances/resumes the canonical updater before checking each fund's actual
history. No new schema, bootstrap, financial formula or UI change is introduced.

A complete result also requires the model to use the exact target-day SeriesX
sum, the verified AUA of 8,000 million, unchanged anchored calculation and valid
95% bounds. GitHub Actions success alone is not an AUM-complete assertion.

The bot creates one assigned tracking issue and sends no waiting comments.
Completion is a bot-authored, persistent marker comment mentioning the owner.
Duplicate checks, retries and interrupted issue closure cannot repeat the
financial job after that marker. The issue is then closed. Closing the issue
manually also stops this watch. Future hourly invocations only check its closed
state, without reading/writing Sites or sending further completion messages.
Disable this workflow manually to remove those lightweight status invocations;
do not disable pages.yml or the daily external scheduler.

Notifications appear in GitHub Notifications; email/mobile delivery follows
the owner's GitHub settings. Existing global workflow-run notification settings
are not modified. A notification-channel test is separately labeled and must
not claim target-date completeness. Fatal runner failures may still generate
GitHub's own workflow notifications according to those existing settings.

Local cannot receive filesystem writes while Windows is off. It obtains the
same canonical snapshot/cache through the existing proxy when opened/online.
No ACL, shortcut, registry or URL changes are required.

Release only the new watcher script, isolated tests, workflow and this runbook
to GitHub with [skip ci], preventing the old push-triggered Pages deployment.
The watcher itself never builds or publishes Pages/Sites code. Keep current
Sites release identity, audience, D1/R2 and unrelated dirty work unchanged.
